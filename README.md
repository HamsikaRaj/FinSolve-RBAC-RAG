# FinSolve AI — RBAC-Enforced RAG Chatbot

An internal enterprise chatbot for a FinTech company that combines **Role-Based Access Control (RBAC)** with **Retrieval-Augmented Generation (RAG)**. Employees ask natural-language questions and receive answers sourced exclusively from documents their role is authorised to access — enforced at the vector-search level, not just at the prompt level.

---

## Architecture

```
┌─────────────────┐     JWT      ┌──────────────────────────────────────┐
│  Streamlit UI   │ ──────────▶  │         FastAPI Backend              │
│  (port 8501)    │ ◀──────────  │         (port 8000)                  │
└─────────────────┘   answers    │                                      │
                                 │  /login  →  verify creds, issue JWT  │
                                 │  /chat   →  RBAC filter → RAG → LLM  │
                                 └────────────┬─────────────────────────┘
                                              │
                         ┌────────────────────┼────────────────────┐
                         ▼                    ▼                    ▼
                   ┌──────────┐       ┌──────────────┐    ┌──────────────┐
                   │  Qdrant  │       │  Sentence    │    │   Claude     │
                   │ Vector DB│       │ Transformers │    │   Sonnet     │
                   │          │       │ (embeddings) │    │  (Anthropic) │
                   └──────────┘       └──────────────┘    └──────────────┘
```

### How a query flows

1. User logs in → FastAPI verifies credentials against `hr_data.csv` + `auth_users.csv`, returns a **JWT** encoding `role` and `department`
2. User sends a question → JWT is decoded to determine `allowedDepartments`
3. Query is embedded with `all-MiniLM-L6-v2` and searched in Qdrant **with a department filter** — only vectors tagged with allowed departments are retrieved
4. A second RBAC check strips any hits that slipped through
5. Retrieved chunks are passed to **Claude Sonnet** with a strict system prompt — it must answer only from the provided context
6. Answer + source citations returned to the UI

## RBAC Access Matrix

| Role | Assigned to | Can access |
|------|------------|------------|
| `exec` | C-Level | Finance · Marketing · HR · Engineering · General |
| `finance` | Finance dept | Finance · General |
| `marketing` | Marketing dept | Marketing · General |
| `hr` | HR dept | HR · General |
| `engineering` | Engineering / IT / QA / DevOps | Engineering · General |
| `employee` | All other departments | General only |

> Roles are derived automatically from the employee's department in `hr_data.csv` — no manual assignment needed.

## Data

```
data/
├── finance/          # Quarterly financial reports 2024 (Q1–Q4) + annual summary
├── marketing/        # Quarterly marketing reports 2024 (Q1–Q4) + annual
├── engineering/      # Engineering master doc (architecture, CI/CD, security, compliance)
├── general/          # Employee handbook (HR policies, conduct, leave, benefits)
└── hr/
    ├── hr_data.csv        # 100 employee records (demographics, performance, attendance)
    └── auth_users.csv     # Hashed passwords (generated by createAuthUsers.py)
```

All documents are ingested as vector chunks tagged with their `department` — this tag is the RBAC enforcement key in Qdrant.

## Getting Started

### Prerequisites

- Python 3.10+
- [Qdrant](https://qdrant.tech/documentation/quick-start/) running locally on port `6333`
- An [Anthropic API key](https://console.anthropic.com/)

### 1. Install dependencies

```bash
pip install -r requirements.txt
```

### 2. Configure environment

Create a `.env` file in the project root:

```env
ANTHROPIC_API_KEY=sk-ant-...

# Optional overrides (defaults shown)
QDRANT_URL=http://localhost:6333
QDRANT_COLLECTION=finsolve_rag
EMBED_MODEL=sentence-transformers/all-MiniLM-L6-v2
ANTHROPIC_MODEL=claude-sonnet-4-5
JWT_SECRET=change_me_in_production
JWT_EXP_SECONDS=3600
```

### 3. Start Qdrant

```bash
# Docker
docker run -p 6333:6333 qdrant/qdrant

# Or download the binary from https://github.com/qdrant/qdrant/releases
./qdrant
```

### 4. Generate auth credentials

```bash
python createAuthUsers.py
```

This reads `data/hr/hr_data.csv` and writes hashed passwords to `data/hr/auth_users.csv`.  
**Demo password pattern:** `Fin@<last4digits>` — e.g. employee `FINEMP1001` → `Fin@1001`

### 5. Ingest documents

```bash
python ingestQdrant.py
```

Chunks all Markdown docs and HR CSV records, embeds them, and upserts into Qdrant with department metadata. Prints a summary:

```
Ingested finance/quarterly_financial_report.md → 20 chunks
Ingested engineering/engineering_master_doc.md → 81 chunks
...
Done. Total chunks indexed: 225
```

### 6. Start the API

```bash
uvicorn app:app --host 127.0.0.1 --port 8000
```

### 7. Start the UI

```bash
streamlit run streamlitApp.py --server.port 8501
```

Open **http://localhost:8501** in your browser.

## API Reference

### `POST /login`

```json
// Request
{ "employeeId": "FINEMP1001", "password": "Fin@1001" }

// Response
{
  "employeeId": "FINEMP1001",
  "fullName": "Isha Chowdhury",
  "role": "finance",
  "department": "Finance",
  "accessToken": "<jwt>",
  "tokenType": "bearer"
}
```

### `POST /chat`

Requires `Authorization: Bearer <token>` header.

```json
// Request
{ "message": "What was Q1 2024 revenue?" }

// Response
{
  "answer": "Q1 2024 revenue was $2.1 billion, up 22% year-over-year.",
  "sources": [
    { "source": "finance/quarterly_financial_report.md", "department": "finance", "chunkId": 12, "score": 0.91 }
  ],
  "debug": { "role": "finance", "allowedDepartments": ["finance", "general"] }
}
```

## Security Notes

- Passwords are hashed with **PBKDF2-SHA256** (no bcrypt dependency issues on macOS/arm64)
- JWTs are signed with HS256; set a strong `JWT_SECRET` in production
- RBAC is enforced **twice**: at the Qdrant query filter level and again on the returned results before they reach the LLM
- The `.env` file is gitignored — never commit API keys
